# 🚨 Detection Rules – Ubuntu SIEM SOC Lab

This document contains all Splunk SPL detection queries implemented in the Ubuntu SIEM Detection Engineering Lab.

---

# 1️⃣ SSH Brute Force Detection

## 🎯 Objective
Detect repeated failed SSH login attempts from the same source IP.

## 🔍 SPL Query

```spl
index=main sourcetype=linux_secure "Failed password"
| rex "from (?<src_ip>\d+\.\d+\.\d+\.\d+)"
| stats count by src_ip
| where count > 5
```

## 🧠 Detection Logic
- Extract source IP from failed login events
- Count failed attempts per IP
- Trigger alert if attempts exceed threshold

## 🚨 Alert Output Fields
- ALERT_TYPE=SSH_BRUTE_FORCE_LINUX
- SEVERITY=Medium
- STATUS=Open

# 2️⃣ SSH Success After Brute Force

## 🎯 Objective
Detect successful SSH login following multiple failed attempts.

## 🔍 SPL Query

```spl
index=main sourcetype=linux_secure ("Failed password" OR "Accepted password")
| rex "from (?<src_ip>\d+\.\d+\.\d+\.\d+)"
| eval action=case(
    match(_raw,"Failed password"),"failed",
    match(_raw,"Accepted password"),"success"
)
| transaction src_ip maxspan=5m
| search action=failed action=success
```

## 🧠 Detection Logic
- Track both failed and successful login attempts
- Correlate events by source IP
- Trigger when failed attempts are followed by success within 5 minutes

## 🚨 Alert Output Fields
- ALERT_TYPE=SSH_SUCCESS_AFTER_BRUTE_FORCE
- SEVERITY=High
- STATUS=Open

# 3️⃣ SSH Login Followed by Privilege Escalation (MITRE T1068)

## 🎯 Objective
Detect privilege escalation via sudo after SSH login.

## 🔍 SPL Query

```spl
index=main sourcetype=linux_secure ("Accepted password" OR "sudo")
| rex "Accepted password for (?<user>\w+)"
| rex "sudo: (?<sudo_user>\w+)"
| eval actor=coalesce(user, sudo_user)
| eval action=case(
    match(_raw,"Accepted password"),"ssh_success",
    match(_raw,"sudo"),"sudo_usage"
)
| transaction host actor maxspan=5m
| search action=ssh_success action=sudo_usage
```

## 🧠 Detection Logic
- Extract authenticated user
- Detect sudo usage
- Correlate SSH login followed by sudo within 5 minutes
- Identify potential privilege escalation behavior

## 🛡 MITRE Mapping
Technique: T1068 – Privilege Escalation

## 🚨 Alert Output Fields
- ALERT_TYPE=SSH_PRIVILEGE_ESCALATION
- SEVERITY=Critical
- STATUS=Open
- MITRE_TECHNIQUE=T1068

# 4️⃣ Risk Score Aggregation

## 🎯 Objective
Calculate overall security risk score based on alert severity.

## 🔍 SPL Query

```spl
index=main sourcetype=soc_alert earliest=-24h
| eval risk_points=case(
    ALERT_TYPE="SSH_BRUTE_FORCE_LINUX",5,
    ALERT_TYPE="SSH_SUCCESS_AFTER_BRUTE_FORCE",15,
    ALERT_TYPE="SSH_PRIVILEGE_ESCALATION",25
)
| stats sum(risk_points) as Total_Risk_Score
```

## 🧠 Risk Model
- Brute Force = 5 points
- Success After Brute Force = 15 points
- Privilege Escalation = 25 points

# 5️⃣ Incident Status Tracking

## 🎯 Objective
Track open incidents generated by detection alerts.

## 🔍 SPL Query

```spl
index=main sourcetype=soc_alert STATUS=Open earliest=-24h
| stats count by ALERT_TYPE
```

## 🧠 Purpose
- Monitor active security incidents
- Provide SOC operational visibility
- Support incident lifecycle simulation
